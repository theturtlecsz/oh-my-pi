Per-session attribution in `omp stats` flips when two session files are created in the same kernel clock tick. The ingest order sorts files by tier and birth time, but when those tie it falls back to the directory listing position, which is unrelated to creation order, so a fork can land before its parent and claim entries it copied. Session files are named `<timestamp>_<id>.jsonl`, so the file path is the creation order. Break the tie by path instead, so a fork created in the same tick stays behind its parent and the parent keeps ownership. The existing tier order must not change.
