Our workflow stop gate holds a session while the workspace stop is engaged, but prompts that never pass through the normal input path (host resume, the `.` and `c` shortcuts, RPC `/`) still start a turn. I want a stopped workspace to refuse those prompts at before_agent_start, before the turn begins, by reading the stop status directly. The read must not change poll state, notify, or abort. While the first poll is still pending and the workspace is stopped, the prompt is blocked. When the read throws or rejects, fall back to the last settled poll: block if that poll is stopped, otherwise allow the prompt.
