We have an intermittent failure in the daemon broker client. After a shutdown, when a superseded connection closes while a new request is already in flight on a replacement connection, that in-flight request is rejected with a connection-closed error instead of completing. The close handler must only fail the requests that were issued on the closing socket, and the reconnect must only run when the closing socket is still the current one. A new socket must not share buffered data with the socket it replaced.
