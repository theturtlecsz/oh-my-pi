## Overview

R1-J measures the Jev pairwise tournament judge (`createJevJudge`) against the
chat judge second family on two surfaces:

1. **Agreement on a labeled pair set** — both judges see each pair in both
   presentation orders; each judge's canonical (order-collapsed) preference is
   scored against the reference label. Off-list answers are impossible by
   construction: the client admits only `{A, B, tie}` and rejects anything else
   as `off_list` before the judge ever sees it.
2. **Cost and wall time for a 20-hypothesis tournament** — each judge runs its
   own Swiss tournament over the same pool and seed, reporting comparisons,
   judge calls, failures, tokens, cost, wall time, and p50/p95 judge-call latency.

Method: the labeled pair set and the 20 hypotheses are frozen inputs. The Jev
judge reads a summary-form write-up (the harness receives `judgeText`, which
`prepareHypotheses` redacts and, for over-limit write-ups, summarizes). The chat
judge draws neutral labels so model identity and slot names cannot bias it.

## What is not measured

- **Calibration.** Jev returns a probability distribution over `{A, B, tie}`;
  this report scores the deterministic outcome the R1 judge derives from it.
  It does not judge whether the probabilities are calibrated.
- **Scientific validity.** Per §8.3, an Elo or judge preference is a search aid,
  never a validity certificate. No ranking here establishes that a hypothesis is
  true.
- **Off-list / off-options behaviour.** Off-list is structurally impossible: the
  client rejects any answer option outside `{A, B, tie}` as `off_list`, and the
  judge throws. The report counts that as a failed call; it measures no answer
  space the client would otherwise accept.
- **Judge-call coverage in the tournament.** A failed judge call is recorded as
  a tie so the tournament completes; the failure count is reported separately and
  is not re-attributed to either hypothesis.
- **State length.** Whether a real candidate write-up exceeds Jev's undocumented
  state size is not measured here; the harness receives the already-redacted,
  already-bounded `judgeText`.

## Where the pieces live

- `docs/reports/jev-measurement/tournament-harness.ts` — injected-judge harness
  (labeled-pair agreement plus 20-hypothesis benchmark). Fetches nothing, holds
  no credential.
- `docs/reports/jev-measurement/run-tournament.ts` — owner-run CLI and report
  renderer; reads the typed Jev key from `~/.config/omp/jev.env` at run time.
- `docs/reports/jev-measurement/tournament-report-template.md` — this template.
- `docs/reports/jev-measurement/TOURNAMENT-MEASUREMENT.md` — plan and owner-slice
  commands.
- `packages/coding-agent/src/autoresearch/tournament/jev-judge.ts` — the judge.
- `packages/coding-agent/test/jev/tournament-measurement.test.ts` — stub-driven
  tests over the harness; no test reaches the real endpoint.
